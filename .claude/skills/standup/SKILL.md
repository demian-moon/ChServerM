# ChServerM Standup

작업 연속성을 유지하는 스킬. 두 가지 모드로 동작한다.

- 인자 없음 또는 `open` → **오픈 모드** (세션 시작)
- `wrap` / `close` / `마무리` → **랩 모드** (세션 종료)

## 대상 파일

| 경로 | 역할 | 쓰기 |
|---|---|---|
| `docs/ROADMAP.md` | 해야 할 일. 체크박스가 유일한 진행률 기준 | 랩 모드에서 체크박스 갱신 |
| `docs/standup/STANDUP.md` | 현재 상태 스냅샷. 항상 최신 1개 | 랩 모드에서 전체 교체 |
| `docs/standup/history/YYYY-MM-DD.md` | 일별 아카이브 | 랩 모드에서 신규 생성(추가 전용) |
| `docs/DECISIONS.md` | ADR 로그 | 결정이 있었을 때만 추가 |
| `docs/BENCHMARKS.md` | 성능 측정 기록 | 측정했을 때만 추가 |

날짜는 반드시 `<system-reminder>`의 `currentDate` 또는 `git log`의 실제 커밋 날짜를 쓴다. 추측하지 않는다.

## 오픈 모드 (`/standup`)

세션을 시작할 때 "지금 어디까지 왔고, 다음에 뭘 해야 하는가"를 확정한다. **읽기만 한다. 파일을 수정하지 않는다.**

### 절차

1. **상태 수집** — 다음을 한 번에(병렬로) 실행한다.
   - `docs/standup/STANDUP.md` 읽기 (없으면 첫 세션으로 취급)
   - `docs/ROADMAP.md` 읽기 — 미완료 체크박스 파악
   - `git log --oneline -20` / `git status --short` — 실제로 커밋된 것과 미커밋 작업물
   - `docs/standup/history/` 최근 파일 1~2개 (STANDUP.md와 어긋나는지 교차 검증)

2. **불일치 검증** — STANDUP.md가 "완료"라고 적은 항목이 git log에 없으면 문서를 신뢰하지 않는다. **git이 사실의 최종 근거다.** 불일치는 보고에 명시한다.

3. **미완료 작업 파악** — 미커밋 변경, 실패하는 테스트, 반쯤 만든 추상화가 있으면 이것이 최우선 후보다.

4. **보고** — 아래 형식으로 사용자에게 출력한다. 파일에 쓰지 않는다.

```markdown
## 스탠드업 — {날짜}

**지난 작업** (마지막 스탠드업 이후)
- {커밋/변경 요약, 근거 커밋 해시}

**현재 상태**
- 로드맵 단계: {Phase N — 제목} ({완료}/{전체} 항목)
- 작업 트리: {clean | 미커밋 파일 N개}
- 진행 중: {끝나지 않은 작업, 없으면 "없음"}

**오늘 할 일** (우선순위 순)
1. {항목} — 근거: {ROADMAP 항목 또는 블로커 해소}
2. ...

**블로커 / 결정 필요**
- {항목, 없으면 "없음"}
```

5. 사용자가 확인하면 1번 항목부터 작업을 시작한다. 사용자 승인 없이 로드맵 순서를 바꾸지 않는다.

### 첫 세션 (STANDUP.md가 비어 있을 때)
ROADMAP.md의 Phase 0 첫 항목을 "오늘 할 일"로 제시하고, 지난 작업은 `git log`만으로 채운다.

## 랩 모드 (`/standup wrap`)

세션을 닫을 때 실제 진행분을 문서에 확정한다. **여기서만 파일을 쓴다.**

### 절차

1. **실제 진행분 수집** — 이번 세션의 대화 내용 + `git log` + `git status`로 실제 한 일을 파악한다. 계획했지만 안 한 것은 완료로 적지 않는다.

2. **ROADMAP.md 갱신** — 완료된 항목만 `- [ ]` → `- [x]`로 바꾼다. 부분 완료는 체크하지 않고 항목 뒤에 `(진행 중: {남은 것})`을 붙인다. 새로 발견된 작업은 해당 Phase에 항목으로 추가한다.

3. **history 아카이브 생성** — `docs/standup/history/{YYYY-MM-DD}.md`:

```markdown
# {YYYY-MM-DD}

## 한 일
- {작업} (`{커밋 해시}`)

## 결정
- {결정 내용 → ADR-XXXX} (없으면 "없음")

## 측정
- {벤치마크 결과 요약} (없으면 "없음")

## 막힌 것 / 미완료
- {항목}

## 다음
1. {다음 세션 최우선 항목}
```

같은 날짜 파일이 이미 있으면 덮어쓰지 말고 섹션을 이어 붙인다.

4. **STANDUP.md 전체 교체** — 최신 스냅샷 하나만 유지한다:

```markdown
# ChServerM — 현재 상태

**최종 갱신**: {YYYY-MM-DD}
**현재 단계**: Phase {N} — {제목} ({완료}/{전체})

## 완료된 것
- {누적 주요 성과, 5~10줄 이내로 유지}

## 진행 중
- {미완료 작업과 남은 범위}

## 다음 (우선순위 순)
1. {항목}
2. {항목}
3. {항목}

## 블로커 / 열린 결정
- {항목}

## 참조
- 상세 이력: `docs/standup/history/`
- 계획: `docs/ROADMAP.md`
- 설계 결정: `docs/DECISIONS.md`
```

5. **ADR / 벤치마크 반영** — 이번 세션에 라이브러리 선택이나 아키텍처 결정이 있었으면 `docs/DECISIONS.md`에 ADR을 추가한다(대안·탈락 이유 필수). 성능 측정을 했으면 `docs/BENCHMARKS.md`에 수치를 남긴다.

6. **커밋** — 문서 변경분만 묶어서 커밋한다.
   ```
   chore(standup): {YYYY-MM-DD}
   ```
   본문에 한 일 요약을 넣는다. **푸시는 사용자가 명시적으로 요청할 때만 한다.**
   코드 변경이 미커밋 상태로 남아 있으면 함께 커밋하지 말고, 사용자에게 알린 뒤 어떻게 할지 확인한다.

7. **요약 출력** — 갱신한 파일 목록과 다음 세션 첫 작업을 한 문단으로 보고한다.

---

## 규칙

- **문서보다 git을 믿는다.** 문서와 커밋 이력이 다르면 커밋 이력이 맞다. 문서를 고치고 불일치를 보고한다.
- **완료를 부풀리지 않는다.** 테스트가 깨져 있거나 벤치마크가 없으면 그 항목은 완료가 아니다.
- **history는 추가 전용.** 과거 기록을 다시 쓰지 않는다.
- **STANDUP.md는 짧게 유지한다.** 상세 서사는 history로 밀어낸다. 이 파일이 길어지면 세션 시작 비용이 커진다.
- 랩 모드는 세션 종료 시점에만 실행한다. 세션 도중 문서를 갱신하려면 사용자에게 확인한다.
