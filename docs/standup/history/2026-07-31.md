## 레거시 분석 핵심 결과

**코드 구성** — 승계·개작 45% / **미참조 35%** / 주석 11% / 명시적 폐기 9%.
실제 동작하며 승계 가치가 있는 코드는 절반 이하이고, 그 안에서도 **치명 버그 40건 이상**.

**승계 자산 22종 확정.** 상위 3개:
1. `oid % n` 샤딩 (→ ADR-0005)
2. 5단 계층적 타이밍 휠 (Kafka/Netty 계열, 삽입 O(1)·틱당 O(1))
3. 상태 기반 패킷 화이트리스트 (Composite + Builder)

**결함 원인 7종으로 수렴.** 특히 두 가지가 관통:
- **(A)** 리소스 소유권이 타입이 아니라 주석에만 있다 → Phase 3에서 타입화가 유일한 구조적 해결
- **(C)** 조용히 실패한다 — 체크섬·압축·재시도·만료·백프레셔·콜라이더 비활성화가 **전부 무동작**.
  원인은 로그 레벨 부재 + 설정 파일 없으면 로깅 전면 소멸 + 메트릭 전무 → Phase 11 설계 목표로

**초기 판정 15건 정정.** 파일명·주석 기반 추정이 틀린 사례가 다수 —
`QuadTreeM` 빈 파일, `FileWatcherSystemM`/`MemoryPoolM`/`StackMemAllocM` 참조 0,
체크섬 검증이 `return true`, AES-256이 아니라 AES-128, 압축이 한 번도 실행되지 않음.
`docs/LEGACY-INVENTORY.md`에 **"파일명과 주석으로 판정하면 안 된다"**는 교훈으로 보존.
