### 1. 버전 협상 핸드셰이크 와이어 구현 — ADR-0017 잔여 해소 (`2fcb199`, `6d70037`)

- **`VersionHandshakeCodec`(Core 신설)** — `ClientHello`(40005, 헤더16B+`[Min,Max]`4B) →
  `ServerHello`(40006, +2B) / 거부 = `ConnectionRejected`(40004, +사유·서버구간 6B, R-3)의
  **영구 동결** 코덱. 프레이밍 어댑터가 아니라 Core 인 이유: 부트스트랩을 교체 가능한
  축에 얹으면 축 교체가 와이어를 깨는 모순(R-2) — varint 와이어에는 버전 필드 자체가
  없음을 확인. 고정 헤더 v1 레이아웃의 의도적 중복은 `FrameHeaderCodec` 교차 검증
  테스트가 지킨다. 파싱은 엄격(전 고정 필드 검증), 실패는 값(T-16)
- **호스팅 통합** — `UseVersionNegotiation()` 양쪽 빌더. 서버는
  `Secured(→ Negotiating(→ Framed))` 감싸기로 **협상이 TLS 채널 안**임을 조립이
  강제(R-4 구조 충족). 핸드셰이크가 정확히 자기 바이트만 소비 — 파이프라인으로
  뒤따라온 앱 프레임 유실 없음. 무응답 = 타임아웃 절단(T-16), 결과 =
  `IProtocolVersionFeature` + 버전별 로그(R-5, 카운터 승격은 Phase 11)
- 클라이언트 거부 = `VersionNegotiationException`(서버 지원 구간 포함 — "업데이트 필요"
  안내 근거). 종단 테스트 8종(합의/거부+생존/비협상 첫 프레임/무응답 타임아웃/TLS 안
  협상/동결 교차 검증), 5회 반복 경합 없음

### 2. 인증 축 — T-05·T-20 완화 완결 (`aff7942`, `9a7297d`, `f47967b`, `2cabad9`)

- **설계 제시 → 사용자 재검토 요청 → 적대적 재검토로 4점 보강 → 4개 결정 승인** 후 구현:
  ① `AuthenticateAsync(MessageContext)` 단일 인자(토큰 중복 제거) ② 페이로드 수명 계약
  명시(await 전 복사 — 레거시 ToArray 위반의 재발 방지) ③ 리플레이 가드
  **검증→클레임 순서** 계약(역순은 쓰레기 토큰으로 가드 포화 = 로그인 DoS)
  ④ 조립 순서 검증(인증이 필터보다 바깥이면 `Build()` 예외)
- **`AuthenticationMiddleware`** — 실패 = `next` 미호출 + **옵션 무관** 6000 종료.
  전용 `DispatchStatus.RejectedByAuthentication`(8) 신설: `RejectedByPolicy` 재사용 시
  `CloseOnPolicyRejection` 하나로 인증 실패가 통과하는 구멍(T-20 재발 경로).
  성공 = `GrantedStates` **상태 대체 전이** — "인증됨" 별도 플래그를 두지 않아
  인증 여부와 허용 메시지 집합이 어긋날 표면 제거(T-19 필터와 한 몸)
- **`InMemoryTokenReplayGuard`** — 유계(포화 = 신규 거부 + 경고, 9.6) + TTL(메모리
  유계 장치). 동시 클레임은 원자적 `TryAdd`/`TryUpdate` 로 정확히 하나만 승리,
  정리는 타이머 없이(9.5) 포화 시점에만 + `Interlocked` 게이트 해제는 `finally`(9.2).
  "같은 토큰 두 번째 커넥션 거부"가 T-05 실증 테스트
- **`ChServerM.Security.AspNetIdentity` 신설(ADR-0018)** — 레거시 유일 승계 자산
  (`AuthM` 의 `PasswordHasher`)의 어댑터. 같은 라이브러리·형식이라 **기존 계정 해시
  그대로 검증**(테스트 고정 — 계정 이전 경로). 결함 4종 역해소: 1회 생성 재사용 /
  반복 횟수 생성자 명시(기본 OWASP 600,000) / 공개 축 / `SuccessRehashNeeded` 표면화

  실패"(T-16) 계약은 어댑터 변환 계층의 몫이다
