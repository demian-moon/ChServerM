  다중 세그먼트는 풀 대여 복사 + `finally` 반납
- **축 증명 완성(DoD-5)**: `SerializerSwapTests` — 같은 핸들러 코드 ×
  Utf8/MemoryPack/Protobuf/FlatSharp 교체

- 빌드 인프라: FlatSharp.Compiler(net9 도구)가 .NET 10 단독 환경에서 실행 거부 →

## 배운 것 (같은 실수 반복 방지)

- **포맷의 스키마 진화는 "방향"까지 검증해야 한다** — MemoryPack 기본 모드는
  구데이터→신리더만 허용(부족분 기본값)이고 신데이터→구리더는 실패한다.
  롤링 배포에서 반드시 발생하는 방향이 실패 쪽이다. 가정(양방향 비호환)은 틀렸고
  실측이 정정했다 — 호환성 주장은 양방향 테스트 없이 적지 않는다
- **교차 환경 비교 금지 규칙이 실제로 작동했다** — varint(ENV-B)와 고정 헤더(ENV-A
  기존 수치)를 비교하려다 규칙에 걸려 고정 헤더를 ENV-B 로 재측정했고, 그 재측정이
  "고정 헤더 34ns"(ENV-A 29ns 와 다름)를 드러냈다. 규칙을 지키지 않았으면 잘못된
  비율을 기록했을 것이다
- **벤치 대결은 불리한 쪽에 기울여 설계한다** — Kestrel 프로토타입에서 프로덕션
  기능을 뺀 채(=Kestrel 유리) 대결시켰고, 그래도 동률이라 결론이 강해졌다
- **빌드 타임 도구의 런타임 요구는 SDK 고정과 충돌할 수 있다** — FlatSharp.Compiler
  (net9)가 global.json 10.x 단독 환경에서 거부. 롤포워드를 빌드 스크립트에 고정해
  로컬·CI 가 같은 조건이 되게 했다
