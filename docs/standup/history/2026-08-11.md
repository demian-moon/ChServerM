  무관한 이유로도 오른다. 세대는 **구성원이 실제로 달라졌을 때만** 오른다.

## 배운 것

- **⭐⭐ 확인하러 갔다가 이전 결론의 <i>기준</i>이 틀렸음을 알았다.** ADR-0051 은
  "미처리 대여물이 **설정 용량**에 비례하면 함정" 이라 적고 `PooledBufferWriter` 를 같은
  성질로 분류했는데, 재 보니 아니었다.
  **붙들고만 있는 대여물은 버킷을 놓고 경쟁하지 않는다. 경쟁하는 것은 동시에 반납되는 것이다.**
  정정된 기준: *동시에 붙들린 수*가 아니라 **반납이 설정 용량 규모로 몰리는가**
- **⭐ 헤드라인이 진짜 비용을 가린다.** "할당 0" 은 맞지만 그 사용법의 실제 비용은
  **상주 메모리 80 MiB**(1만 × 8 KiB)다. 0 이라는 숫자가 그 크기를 안 보이게 한다
- **⭐⭐ 같은 실수가 다른 API 에서 또 나온다.** Consul 은 **잠금 획득 실패도 HTTP 200 +
  본문 `false`** 로 돌려준다 — ADR-0051 의 `PipeWriter.FlushAsync`(닫힌 상대에도 예외를
  던지지 않는다)와 **정확히 같은 모양**이다. 그때 적은 교훈("이 API 는 실패를 반환값으로
  알리는가를 API 마다 물어야 한다")을 이번에는 **미리 적용해서 처음부터 막았고**,
  고의 회귀가 그것을 확인해 줬다
- **⭐ 제공자의 "세대" 와 우리 "세대" 는 이름만 같다.** 그대로 실었으면 절단·되돌아감·
  헛깨어남 셋이 한꺼번에 들어왔을 것이다. **닮은 이름을 만나면 보장을 비교한다**
- **⚠ 어댑터에 등록 기능을 넣지 않은 것이 테스트를 살렸다.** 넣었다면 테스트가
  **어댑터가 쓴 것을 어댑터가 읽는 순환**이 됐다
- **⚠ 분석기가 측정 오류를 잡았다.** CA1859 가 벤치 `Fill` 의 인터페이스 매개변수를
  지적했는데, 그 루프는 측정 대상 안이라 인터페이스 디스패치가 수치에 섞였을 것이다

## 배운 것

- **⭐⭐ 커넥션 하나짜리 테스트는 HTTP/2 의 거짓 초록을 만든다.** 같은 연결의 **두 번째
  스트림부터** HEADERS 가 본문 첫 쓰기까지 클라이언트 버퍼에 갇힌다 — 첫 스트림은 연결
  수립 플러시에 편승해 통과하므로 단일 커넥션 테스트는 전부 초록이었다. 해법은 펌프 시작
  직후 빈 플러시(gRPC 와 같은 방식). **"작은 조건에서 전부 통과" 는 규모 조건 하나로
  뒤집힌다** — 어제의 1만 커넥션 재측정과 같은 교훈이 전송 축에서 재현됐다
- **⭐⭐ 정리 경로의 예외 하나가 프로세스를 죽였다.** Kestrel 요청 본문 리더는 스트림
  리셋 후 `CancelPendingRead`/`CompleteAsync` 에서도 던지고, `IHttpApplication` 밖으로
  새면 **테스트 호스트가 통째로 크래시**한다(처음엔 교착으로 오판했다 — 크래시는 로그도
  없이 멈춤과 똑같이 보인다). "종료 경로의 예외는 종료를 막을 이유가 없다" 를 전 경로에
  적용해 해소. 9.2(finally 복원)의 이웃 규율이다
- **⭐ "무상태 모드" 는 기능이 아니라 조립이었다.** 실행 모델 미지정 + `ISessionStore`
  CAS 만 쓰는 핸들러 = 무상태 모드. 새 장치 0개. ADR-0004 가 설계한 대로 축 조합이
  워크로드를 만든다는 것이 실증된 자리
- **⚠ 관찰 항목은 미루면 쌓이고, 재면 하루에 셋이 닫힌다.** 어제 남긴 측정 공백 둘과
  여러 세션 묵은 Redis Cluster 가 오늘 전부 종결 — "기전을 안다" 와 "크기를 안다" 사이의
  거리는 벤치 하나 거리였다

## 배운 것

- **⭐ 세 번째 Kestrel 계열부터는 함정 목록이 체크리스트가 된다.** HTTP 에서 실측으로
  배운 둘(정리 경로 예외의 프로세스 격추·Abort 의 EOF/예외 비대칭)을 WS·QUIC 에 처음부터
  반영했고, 둘 다 **첫 실행에 통과**했다. 결함을 ADR 에 "무엇을 막는가"로 적어 두는
  이유가 이것이다
- **⭐ QUIC 스트림 열기는 로컬 연산이다** — 드레인 거부가 연결 시점이 아니라 첫

- **⭐ 전송 추가 비용이 항목당 `[InlineData]` 한 줄로 수렴했다** — 다섯 번째 전송이

## 배운 것

- **⭐⭐ 문서의 성능 주장이 실측으로 반증됐다.** 옵션 문서 초안은 "스핀 1ms 로 지터
  밀리초 미만"이라 적었는데, `Thread.Sleep` 초과 수면(≈15.6ms)이 1ms 스핀 구간을
  통째로 건너뛰어 순수 슬립과 사실상 같았다. 스핀이 성립하는 조건은 ① 간격 ≤ 스핀
  구간, ② 스핀 구간 > OS 슬립 해상도 — 둘뿐이다. "측정 없는 최적화 금지"가 문서
  주장에도 적용된다는 실례
- **⭐ 취소 콜백의 시점은 자료구조가 아니라 계약 문제다.** 슬롯 도달까지 미루면 30일
  타이머의 취소 통지가 30일 뒤에 온다 — 콜백은 취소자 스레드에서 즉시, 물리 제거만
  드라이버가. 이 분리가 단일 드라이버 계약과 즉시성을 동시에 지킨다
- **⭐ ABA 는 세대와 상태를 한 워드에 패킹해야 CAS 하나로 닫힌다.** 따로 두면 "세대
  확인 후 상태 CAS" 사이에 재사용이 끼어든다 — 검사와 전이가 같은 원자 연산이어야 한다
- **⚠ 증분 빌드는 경고를 숨긴다.** QUIC 세션의 경고 2건이 `--no-incremental` 에서만
  드러났다 — "경고 0" 주장은 전체 재빌드로 검증해야 한다
