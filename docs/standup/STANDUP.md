## 이번에 배운 것 (같은 실수 반복 방지)

- **검증 장치는 실전 경로를 검증해야 한다.** 파티션 고정은 테스트·벤치마크·통합이 전부
  녹색인 채로 깨져 있었다 — 테스트는 실전과 다른 await 조합을, 벤치마크는 청크 단위를,
  통합은 빌더 우회 경로를 검증하고 있었다. "무엇을 검증하는가"가 "통과하는가"보다 먼저다
- **스레드 어피니티로 배타성을 얻는 설계는 `ConfigureAwait(false)` 규약과 구조적으로
  충돌한다.** 배타성이 필요하면 완료 대기로 강제한다(ADR-0008)
- **측정이 나쁘게 나오면 그대로 기록한다.** 역확장·할당 실측을 BENCHMARKS 에 그대로 남겼다.
  구 설계의 "비용 0"은 비용이 없던 게 아니라 안 보였던 것이다
- **체크박스는 DoD 를 통과했을 때만.** 벤치 수치 없는 성능 항목 `[x]` 2건을 되돌렸다

## 작업 방식

- **코드는 사용자 지시 후에만 작성한다.** 먼저 대상·시그니처·근거를 제시하고 승인받는다.
  조사·분석·문서는 자율
- 주석은 한글 4계층(8.2) / public 표면 변경 시 승인 파일 갱신(8.1) / 동시성은 9절 선행
- 분석기 정책 완화 시 근거 기록. CI 확인은 `gh` CLI
- 커밋: 코드와 문서 분리. 문서는 `/standup wrap` 에서 `chore(standup)`

