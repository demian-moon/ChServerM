# ChServerM — 현재 상태

**최종 갱신**: 2026-08-09
**현재 단계**: **Part III 종료 (Phase 12 = 10/10)** · 다음은 Phase 13 세션 & 영속화 (전체 121/222)

## 완료된 것

- **Part I~II 골격** — Core 무의존 추상화, 고정 헤더 프레이밍, TCP/Kestrel 전송, 직렬화 4종,
  소스 제너레이터 디스패치, 파티션 실행 모델, TLS, 미들웨어 파이프라인
- **Part III 운영 축(Phase 9~12) 완결** — 수용 제어(전역·주소별·부하 기반), 속도 제한,
  우아한 열화, 헬스체크/HTTP 프로브, 크래시 처리, 메트릭·추적·런타임 진단, MEL 로깅 어댑터
- **회귀 방어 3종** — 할당 게이트(상시) · **비율 게이트**(CI 상시, ADR-0032) ·
  확장성 게이트(수동). **셋 다 고의 회귀를 실제로 잡는 것까지 검증**했다
- **성능 기준선 실측 확정** — 169k RPS · 1만 접속 · 프레임당 0B · 라우팅 0.69ns ·
  코어 확장 **14.79×/16코어**(머신 ALU 천장의 99.9%) · AOT 기동 2.8× · GC 모드 A/B
- **프레임워크 세금 측정** — raw Kestrel 바닥선 대비 저부하 −13.5%, 고동시성 −3.3%이지만
  **p99 −34%**(파티션 모델이 꼬리 지연에서 값을 낸다는 첫 증거)
- `docs/PROFILING.md` — 실제로 떠보고 쓴 프로파일링 워크플로

## 블로커 / 열린 결정

- **GC 기본값은 잠정이다** — `ServerGarbageCollection=true` + DATAS 기본을 유지했지만
  루프백 측정에서는 Workstation 이 p99 가 더 좋았다. 전용 머신 재측정 전까지 확정 아님
- **CI 스케줄 미정** — 24h soak 를 언제 어떻게 돌릴지(비율 게이트는 이미 CI 상시)
- **레거시 자격증명**(`ServerGlobals.cs:103` MongoDB) — 유출된 것으로 취급. 로컬 개발 외로
  재사용한다면 폐기·교체 필요. **사용자 확인 대기** (Phase 13 의 MongoDB 어댑터 검토와 직결)
- **보류 유지** — Bulkhead 강제(핸들러 타임아웃) / `FramesSent`(FrameWriter static 제약) /
  Phase 7 누락 핸들러 검출(메시지 레지스트리 선행)
