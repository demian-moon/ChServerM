# ChServerM — 현재 상태

**최종 갱신**: 2026-08-08
**현재 단계**: Phase 12 — 성능 검증 & 회귀 방어 (116/222 · Phase 12 는 5/10)

## 완료된 것

- **Part I~III 골격 완결** — Core 무의존 추상화, 고정 헤더 프레이밍, TCP/Kestrel 전송,
  직렬화 4종, 소스 제너레이터 디스패치, 파티션 실행 모델, TLS, 미들웨어 파이프라인
- **Phase 9~11 운영 축 완결** — 수용 제어(전역·주소별·부하 기반), 속도 제한, 우아한 열화,
  헬스체크/HTTP 프로브, 크래시 처리, 메트릭·추적·런타임 진단, MEL 로깅 어댑터
- **Phase 12 착수** — 성능 기준선 실측 확정, **할당 회귀 게이트**(고의 회귀를 실제로 잡는지까지
  테스트로 고정), LoadRunner 무한 루프 수정, Native AOT vs JIT 실측(기동 2.8×·메모리 2.8×)
- **⚠ GC 설정 결함 발견·수정**(ADR-0031) — `ServerGarbageCollector` 오타로 **3개월간
  Workstation GC** 로 돌았다. A/B 결과 **처리량은 GC 모드에 ±2% 이내로 둔감**(= 무할당 설계가
  작동한다는 증거), DATAS 는 p99 46~85% 악화, DATAS 끈 ServerGC 는 워킹셋 10배
- 테스트 전 스위트 통과(통합 293 포함), public API 승인 게이트 상시 적용

## 블로커 / 열린 결정

- **GC 기본값은 잠정이다** — `ServerGarbageCollection=true` + DATAS 기본을 유지했지만,
  루프백 측정에서는 Workstation 이 p99 가 더 좋았다. 전용 머신 재측정 전까지 확정 아님
- **CI 환경 미정** — 벤치마크·확장성 게이트와 24h soak 스케줄이 전부 여기에 걸려 있다
- **레거시 자격증명**(`ServerGlobals.cs:103` MongoDB) — 유출된 것으로 취급. 로컬 개발 외로
  재사용한다면 폐기·교체 필요. 사용자 확인 대기
- **보류 유지** — 서킷 브레이커(Phase 13/15) / Bulkhead 강제(핸들러 타임아웃) /
  `FramesSent`(FrameWriter static 제약) / Phase 7 누락 핸들러 검출(메시지 레지스트리 선행)
