## 블로커 / 열린 결정

- **ADR-0005 검증 조건 미충족** — 파티션 모델은 구현됐지만 **"코어 수 대비 선형 확장"이
  증명되지 않았다.** 증명 못 하면 이 결정은 무효다
- **ADR-0001 미결** — 순수 `Socket` 프로토타입은 완성. Kestrel Socket Transport 버전과
  벤치마크로 붙여야 확정된다. `IServerTransport`가 중립이라 두 구현 공존은 가능
- **ADR-0002 남은 부분** — 페이로드 직렬화 기본값. Phase 6 4자 벤치마크
- **ADR-0007 미해결 항목** — 조각 재조립이 생기면 재조립 버퍼 상한·만료가 별도로 필요하다
- **편의 문법 의존 방향** — `.UseTcp(port)`는 전송이 `Hosting`을 참조해야 성립하는데
  `Hosting → 어댑터 → Core` 방향을 뒤집는다. 지금은 방향을 지키는 쪽을 택했다
- 벤치마크 기준선 없음 — 성능 수치는 **레거시 실측**(`docs/legacy/00-overview.md` 5절)과
  할당 0 확인만 있다

## 이번에 배운 것 (같은 실수 반복 방지)

- **축 간 제약은 조립 계층에서만 검사할 수 있다.** 각 축은 자기 설정만 검증한다.
  최대 프레임 > 전송 버퍼가 그 예이고, 어긋나면 **큰 메시지 하나에서 예외도 로그도 없이 교착**한다.
  `CompositionGuard` 형태로 계속 늘려간다 (ADR-0007)
- **파이프 소유권 규약을 코드가 어길 수 있다.** `IConnection.Input`은 읽기 루프 하나가 소유하는데
  샘플이 이를 어겨 `PipeReader`가 던졌다. 문서에 적힌 규약이 곧 강제는 아니다
- **테스트 호스트가 죽으면 원인이 스택으로 안 나온다.** 클래스 → 메서드 순으로 좁히고
  독립 재현 프로그램을 만드는 것이 가장 빨랐다
- **"통과"가 "옳음"이 아니다.** 200KB 페이로드가 TCP에서 통과한 것은 커널 버퍼가 흡수한 우연이었다

## 작업 방식

- **코드는 사용자 지시 후에만 작성한다.** 먼저 대상 파일·타입·시그니처·근거를 제시하고 승인을 받는다.
  조사·분석·문서는 자율
- **주석은 한글, 모듈 단위 4계층** (`CLAUDE.md` 8.1). 모듈 주석에 존재 이유·스레드 규약·
  수명 규약·막고 있는 레거시 결함·성능 근거를 담는다
- 동시성 코드는 9절을 먼저 읽는다. 특히 9.1(공유 대신 파티셔닝)·9.2(`finally` 복원)·9.6(유계 큐)
- 승계 대상 구현 전 `docs/legacy/`의 해당 문서를 읽고 **"절대 옮기면 안 되는 것"** 을 체크리스트로 쓴다
- 분석기 정책을 풀 때는 **`.editorconfig`에 근거를 적는다.** 지금까지 푼 것:
  CA1028(와이어 레이아웃), CA1711(BCL 선례), CA1716(C# 전용), Tests/Samples 스코프 5건
- 커밋: 코드와 문서를 분리한다. 문서는 `/standup wrap`에서 `chore(standup)`으로
